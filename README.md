## 2. First-time Setup

Fill in these values in **`.vscode/settings.json`**, under `cmake.configureSettings`:

```json
"cmake.configureSettings": {
    "GCC_PATH": "/path/to/arm-none-eabi-gcc/bin",
    "OPENOCD_BIN": "/path/to/openocd",
    "SDK_ROOT": "../N32WB03x_SDK/N32WB03x_SDK_V2.0.0",
    "BOARD": "N32WB03x_EVAL",
    "CATEGORY": "BLE",
    "PROJECT": "P2PS_OTA",
    "PROBE": "dap",
    "BUILD": "release"
}
```

`GCC_PATH`/`OPENOCD_BIN` are **required, with no auto-detect fallback** — `GCC_PATH` is needed for every build (`make build ...`), `OPENOCD_BIN` only for flashing (`make flash ...`); both are absolute, machine-specific paths. `SDK_ROOT` is the single SDK tree the whole repo builds against — a *relative* path (resolved against `.vscode/`'s own location), so the example value above works unchanged in any clone/copy of this repo; switch SDK versions by editing it and rebuilding.

`BOARD`/`CATEGORY`/`PROJECT` select which project `make build`/`make flash` act on — the literal `Projects/<BOARD>/Applications/<CATEGORY>/<PROJECT>` path segments (run `make list-projects` to see every legal combination). `PROBE`/`BUILD` are the same `dap`/`release` defaults as before, just settings.json-sourced now. With all of these set, the build/flash commands themselves only need the target — see [Building](#4-building)/[Flashing](#5-flashing). Every value here can still be overridden per-invocation on the command line (e.g. `make build APP PROJECT=BEACON`).

Leaving `GCC_PATH`/`OPENOCD_BIN`/`SDK_ROOT`/`BOARD`/`CATEGORY`/`PROJECT` unset fails fast with a clear error pointing back at this file (`PROBE`/`BUILD` have safe hardcoded fallbacks if omitted). This is the single source of truth for both the terminal `make` workflow and VS Code's own CMake Tools extension — no separate machine-local script to keep in sync.

## 3. Project Structure

```
n32wb031_gcc/
├── Projects/                       # Active firmware projects (only thing you build)
│   ├── N32WB03x_EVAL/Applications/
│   │   ├── BLE/BEACON/             # BLE beacon
│   │   ├── BLE/P2PS_OTA/           # P2P Server + FUOTA OTA
│   │   └── STANDALONE/PERIPHERAL/  # Non-BLE peripheral/OTA-bootloader test
│   └── N32WB03x_CUSTOM_BOARD/Applications/
│       └── BLE/P2PS_OTA/           # P2P Server + FUOTA OTA (custom-board copy)
│
├── Utilities/                      # Shared Phase-2 engine: trace, sequencer, timer, LPM, SysTime
│   └── common/                     # dfu_crc.c/.h — shared by every INSTALLER
├── profiles/                       # Custom GATT profiles (P2PS, FUOTA)
├── cmake/                          # Toolchain file
├── openocd/                        # OpenOCD configs + RAM-stub TCL flash script
├── tools/                          # flash.sh, flash_projects.sh, elfsize.sh
├── N32WB03x_SDK/                   # Vendor SDK (V1.3.3 and V2.0.0)
└── N32WB03x_Docs/                  # Reference documentation
```

Every project follows the same layout:
```
<Project>/
├── Common/install_flag.h   # project-local, unique OTA install magic
├── APP/{Core,UserApp,BLE?}/{src,inc}, Linker/, CMakeLists.txt
└── INSTALLER/Core/{src,inc}, Linker/, CMakeLists.txt
```

Run `make list-projects` for the current, authoritative list of every `<CATEGORY> <Project> <TARGET>` combination — it's generated by scanning the tree, not hand-maintained here.

## 4. Building

All commands run from the repo root.

```
make build INSTALLER|APP|ALL
```

`BOARD`/`CATEGORY`/`PROJECT` (from `.vscode/settings.json`, see [First-time Setup](#2-first-time-setup)) select which project — the command itself only needs the target. `ALL` builds INSTALLER then APP. `BUILD` defaults to `release`. There is no SDK-version argument either — the SDK you build against is set once in `.vscode/settings.json`'s `SDK_ROOT`.

**Examples:**

```
make build INSTALLER
make build APP
make build APP BUILD=debug
make build ALL
make build APP CATEGORY=STANDALONE PROJECT=PERIPHERAL   # one-off override, doesn't touch settings.json
```

**Other commands:**

```
make list-projects     # list every <CATEGORY> <Project> <TARGET> combination
make clean-projects    # remove the whole build/ directory (alias for `make clean`)
make clean             # same — remove build/
make size               # show Flash/RAM usage of the last configured build (no build)
make help               # full usage
```

## 5. Flashing

Uses `openocd/flash_n32.tcl` with a GCC-compiled RAM stub to program the Qflash controller — the N32WB031's proprietary flash controller has no standard OpenOCD flash driver. Requires an ST-Link V2 or CMSIS-DAP probe connected via SWD.

```
make flash INSTALLER|APP|ALL
```

Same `BOARD`/`CATEGORY`/`PROJECT` selection as [Building](#4-building). `PROBE` defaults to `dap`. `ALL` does a chip erase, then flashes INSTALLER, then APP.

**Examples:**

```
make flash APP                    # flash just the APP (assumes INSTALLER already on-chip)
make flash ALL                    # blank chip: erase + INSTALLER + APP
make flash APP PROBE=stlink       # force ST-Link instead of CMSIS-DAP
```

## 6. Flash Memory Map

There's no single repo-wide map anymore — each project defines its own APP/INSTALLER addresses and sizes in its own `APP/Linker/*.ld` and `INSTALLER/Linker/*.ld` (`make build`/`make size` read them directly, so they're always the authoritative source).

**SRAM map (48 KB total, applies to every project — shared MCU layout):**

| Region | Address | Size | Owner |
|--------|---------|------|-------|
| BLE ROM working area | `0x20000000` | 16 KB | **BLE ROM — do not touch** |
| User SRAM | `0x20004000` | 32640 B | Stack, heap, `.bss`, `.data` |
| NVM_RAM (`.noinit`) | `0x2000BF80` | 128 B | Reset-persistent variables (`nvm_ram.c/.h`) |

> **NVM_RAM** holds variables decorated with `__attribute__((section(".noinit")))`.
> These survive `NVIC_SystemReset()` and the reset button as long as VDD is held.
> See [SRAM_Retention.md](N32WB03x_Docs/SRAM_Retention.md) for details.
